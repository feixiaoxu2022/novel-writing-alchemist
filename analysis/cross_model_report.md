## 数据有效性说明

**⚠️ 已知数据质量问题：4 个样本因 user_simulator 初始化失败导致异常终止**

**识别标准：**
- 消息数 < 30（正常样本中位数 64，10分位 37）
- 无 `####STOP####` token（81.2% 的成功样本有 STOP）
- User 消息数 < 10（反映 HITL 交互轮次）

**影响比例：**
- EB5-midtrain: 3/24 (12.5%)

**根本原因：**
1. user_simulator 初始化失败（可能原因：网络抖动、API限流、环境变量缺失）

**数据处理：**
- 这 4 个样本**不应计入有效统计**（但因无法重跑，仍保留在数据集中）
- 报告中涉及这 4 个样本的分析结论需谨慎解读
- EB5-midtrain 和 MiniMax-M2.5 的整体得分可能被这些异常样本拉低

**⚠️ 已知框架 bug：request_human_review 参数传递不完整（已修复，但当前数据未重跑）**

在评测执行过程中，executor.py 的 `user_input_callback` 函数存在参数拼接逻辑缺陷：当 Agent 调用 `request_human_review` 工具同时提供 `summary`、`question`、`options` 三个参数时，只有 `summary` 被传递给用户模拟器，`question` 和 `options` 被忽略。

**影响表现：**
- 用户模拟器收到的信息不完整（如只收到"我匹配了3个配方方案"，但看不到具体配方内容）
- 导致模拟器回答不相关（如回答"好，请展示一下这三个方案"，而 Agent 实际已在 `question` 中展示过）
- Agent 需要**再次调用工具展示相同内容**，造成交互轮次增加

**受影响样本统计：**

| 模型 | DSV1受影响 | DSV2受影响 | 合计 | 总样本数 | 影响比例 |
|------|-----------|-----------|------|---------|---------|
| Claude Opus 4.5 | 14 | 24 | 38 | 31 | 122.6% |
| Claude Opus 4.6 | 19 | 15 | 34 | 31 | 109.7% |
| GLM-5 | 38 | 68 | 106 | 31 | 341.9% |
| Qwen 3.5 Plus | 31 | 30 | 61 | 31 | 196.8% |
| Ernie Thinking | 34 | 36 | 70 | 28 | 250.0% |
| Doubao | 8 | 2 | 10 | 31 | 32.3% |
| Gemini 3 Pro | 1 | 1 | 2 | 31 | 6.5% |
| Qwen 3 Max | 3 | 3 | 6 | 31 | 19.4% |
| Kimi k2.5 | 0 | 0 | 0 | 31 | 0% |
| EB5-midtrain | 1 | 18 | 19 | 26 | 73.1% |
| MiniMax M2.5 | 9 | 5 | 14 | 31 | 45.2% |

注：影响比例 > 100% 表示单个样本在多个交互轮次中重复触发该问题。

**对评测结果的影响：**
- **成功率影响：微小**。数据显示大部分受影响样本仍正常完成任务（如 Claude/Doubao/MiniMax 受影响样本 100% 成功）
- **轮次数影响：中等**。每次重复交互增加 2 轮对话（1次 Agent 输出 + 1次 simulator 输出），可能使某些模型的平均轮次数偏高
- **公平性影响：中等**。不同模型因 prompt 风格差异受影响程度不同（Kimi 0% vs GLM-5 341.9%），但由于对成功率影响小，不影响模型排名的基本结论

**修复状态：**
- Bug 已在 2026-03-04 修复（mcp-benchmark commit d47e3d8）
- 当前评测数据未重跑（重跑成本过高且对核心结论影响有限）
- 后续新评测将使用修复后的框架

### 洞察 1：Ernie 在 handoff 前后产出质量断崖式下跌

**DRAMA_001 提供了一个罕见的"对照实验"**：同一个 Ernie、同一个样本，handoff 前后的章节质量形成了鲜明对比。

**handoff 前**（chapter_01\~03，每章 3,964\~4,233 字）——正常的小说正文：

```
顾清寒站在秘境入口前，指尖轻轻抚过腰间的寒霜剑。剑柄上刻着顾氏
家徽——一只展翅欲飞的冰凤，在晨光下泛着冷冽的蓝光。他是顾氏这一代
最杰出的少主，年仅二十岁便已突破金丹期，被誉为"千年难遇的剑道奇才"。
但只有顾清寒自己知道，这"奇才"二字背后是怎样的代价。
```

**turn[74] 发生 handoff**（Agent Handoff: Context compressed to continue task）

**handoff 后**（chapter_05\~18，每章仅 800\~960 字）——章节内容变成大纲而非正文：

```
## 场景1：崖底危机
**场景号**：10-1
**地点**：龙凰巢穴外·悬崖边
**人物**：顾清寒、沈无羁、陆长歌、林婉儿、顾烈
**目的**：逃离轮回宗追杀
**核心动作**：顾烈率黑衣人包围，沈无羁暴走引开追兵
**冲突点**：坠崖途中沈无羁用魔气缓冲……
**情感变化**：绝望→相依→沈无羁在顾清寒耳边低语"下辈子换我护你"
**结果**：两人坠入云雾缭绕的崖底
```

**证据链**：

- handoff 摘要不为空（turn[75] 共 5,982 字），因此退化不是因为空摘要
- 但**摘要内容的差异**才是关键：Ernie 的摘要以"项目管理报告"格式写成——文件列表、进度百分比、里程碑、交接说明。写作风格方面仅有一句泛泛的"Show Don't Tell，通过动作和细节展现"，**没有任何关于已写章节的文风特征、叙事视角、情感表达方式的具体描述**
- 对比 Claude 同一样本的 handoff 摘要（第 1 次 5,133 字）：精确到叙事视角切换规则（"同一场景内不切换"）、肢体接触进度表（逐章列出接触方式和性质递进）、关键章节的必保留台词、比喻系统说明（"偏现代——像被电流击中"）、用户隐性偏好提炼（6 条具体规则）。Claude 后续 2 次 handoff 摘要也保持了同等精度（分别 5,062 和 6,380 字）
- **摘要质量差异直接决定了恢复后的产出质量**：Claude 的下一任拿到摘要后能精确还原文风；Ernie 的下一任只知道"还剩 14 章要写"和文件在哪，不知道应该怎么写
- chapter_04 缺失：handoff 前已提交 ch04 的审阅（摘要中提到已完成），但实际 workspace 中 ch04 文件不存在——handoff 过程中丢失了
- handoff 后一口气连写 ch05\~ch18（14 章），**中间无任何 read 回顾前文或大纲**

**SWEET_001 佐证**：SWEET_001 全程（含 handoff 前的 ch01\~03）章节内容都是大纲而非正文。说明"写大纲而非正文"是 Ernie 的**默认产出模式**（对应检查项"完整叙事文本"），DRAMA_001 前 3 章写成正文可能是因为 writing_log 和大纲刚写入不久、上下文还完整。一旦 handoff 丢失了上下文中的风格锚定，就回退到默认模式。

Claude 对比：Claude 的 DRAMA_001 全部 25 章（31.5 万字）均为连续叙事正文，风格一致。原因有两层：(1) handoff 摘要本身就包含了精确的文风描述和情感刻度表，下一任能直接还原；(2) 恢复后 Claude 还会主动 re-read 关键文件（典型的恢复序列：read chapter_08 → read writing_log → read creative_intent → read outline → read characters → read WRITING_TECHNIQUE_GUIDE → read CONSISTENCY_MANAGEMENT_GUIDE），双重保障产出风格不变。

### 洞察 2：轨迹结构的根本差异——"写完就走" vs "写-查-改循环"

**DRAMA_001 Ernie 轨迹（55 次 tool call）**：

```
[000-001] 读 RECIPE_KNOWLEDGE + schema（2次）
[002-012] 配方交互 request_human_review（6次）+ 读 3 个方向的 creative_intent + 写结果
[013-015] 读 CHARACTER_DESIGN/NAMING/OUTLINE GUIDE（3次）
[016-018] 写 characters / outline / writing_log
[019-020] request_human_review 写作准备 + 写作准备确认
[021] 读 WRITING_TECHNIQUE_GUIDE
[022-024] 写 chapter_01 + 更新 writing_log + 开篇审阅
[025-028] 写 chapter_02 + 更新 writing_log + 审阅
[029-034] 写 chapter_03 + 更新 writing_log + 审阅（2次错误stage）
--- handoff [turn 74] ---
[036] request_human_review 开篇审阅（ch04，但文件已丢失）
[037-040] 读 outline + list_directory + create_directory
[041-054] 一口气连写 chapter_05 到 chapter_18（14章，无中间回顾）
```

关键：**handoff 前 Ernie 其实在做"写一章-更新 log-提交审阅"的循环**（ch01\~03 每章都有这个模式）。但 handoff 后这个循环完全丢失——14 章连写，0 次 read、0 次 writing_log 更新、0 次审阅。

**DRAMA_001 Claude 轨迹（144 次 tool call）**：

```
[000-011] 读 skill + schema + 配方交互 + 写 characters
[012-022] 分幕规划 outline（temp files + merge 脚本 + 验证）
[023] request_human_review 写作准备确认
[024-025] 读 WRITING_TECHNIQUE + CONSISTENCY GUIDE
[026-041] 创建 chapters 目录 + 逐章写作（ch01~ch09，含字数统计）
--- 上下文恢复 ---
[042-048] 读 ch08 + writing_log + creative_intent + outline + characters + 两个 GUIDE（完整恢复序列）
[049-076] 继续写作 ch09~ch25 + 多次字数统计 + 扩写 ch15/19/20
--- 上下文恢复 ---
[077-091] 读文件恢复 + python 脚本分析大纲覆盖度
[092-112] 逐章回读（ch14~ch25）→ 定向扩写 8 个章节
--- 上下文恢复 ---
[113-143] 再次回读 + 继续扩写 ch15/16/18/25 + 字数统计 + 更新 writing_log
```

Claude 的轨迹有三个明确的"写-查-改循环"：

1. **初稿阶段**：写 ch01\~09，每 4 章做一次字数统计
2. **扩写阶段一**：恢复上下文后，先统计字数发现不够，定向扩写 ch15/19/20
3. **扩写阶段二**：用 python 脚本分析"每章 vs 大纲 synopsis 的覆盖度"，逐章回读→评估哪些章节需要加厚→定向扩写

**SWEET_001 对比**：

SWEET_001 Ernie 轨迹（54 次 tool call）同样呈现"一口气写完"模式——连写 18 章无中间回顾。此外有两个独立的问题：(1) 流程顺序错乱——写完 18 章后才做"写作准备确认"的 handoff，本该在写作前完成的确认流程写完之后才做；(2) 工具幻觉——调用了不存在的 `submit_final_answer`（返回 tool not found error），但未从 error 中纠正。

SWEET_001 Claude 轨迹（119 次 tool call）同样有"写-查-改循环"：分幕规划 outline（temp_act1/2/3 + merge 脚本）→ 逐章写作 + 中间 review → 扩写薄弱章节 → 最终字数统计。

### 洞察 5：writing_log 的价值在于持续回顾，而非仅仅创建

| 指标             | DRAMA_001 Ernie                 | DRAMA_001 Claude         | SWEET_001 Ernie        | SWEET_001 Claude       |
| ---------------- | ------------------------------- | ------------------------ | ---------------------- | ---------------------- |
| writing_log 创建 | 是                              | 是                       | **从未创建**     | 是                     |
| 内容             | 完整 Markdown（角色+大纲+进度） | 进度表+字数统计+修改记录 | —                     | 进度+设定确认+修改记录 |

### 跨洞察归因：两个阶段的退化

Ernie 在长篇写作中的退化发生在**两个不同阶段**：

**阶段 A：handoff 前——上下文接近窗口上限时的渐进退化**

随着持续写作，上下文不断增长，Ernie 的产出质量渐进下降。以下证据来自 dsv1（无 handoff）样本，排除了 handoff 的干扰：

*证据 A1：章节字数随上下文增长稳步衰减*

以 NW_CLEAR_MEDIUM_ANGSTY_001（dsv1，40 章，全程无 handoff）为例：

| 章节段 | Ernie 均字符/章 | 相对 ch01-10 | Claude 均字符/章 | 相对 ch01-10 |
|--------|----------------|-------------|-----------------|-------------|
| ch01-10 | 12,964 | 100% | 8,771 | 100% |
| ch11-20 | 4,593 | **35%** | 6,823 | 78% |
| ch21-30 | 3,155 | **24%** | 6,668 | 76% |
| ch31-40 | 2,844 | **22%** | 6,093 | 69% |

Ernie 从第 11 章开始断崖式下降，最终每章字数仅为起始阶段的 22%。同一样本的 Claude 也有缓降（69%），但始终维持在合理水平。NW_IP_MEDIUM_NEUTRAL_001（同为 dsv1，40 章）呈现完全一致的模式。

*不仅是字数缩短，叙事方式本身也在退化*。同一个 ANGSTY_001 样本中：

- ch01\~10（均 5,000+ 字/章）：每章有完整的设定展开、人物内心描写、情节推进，段落饱满
- ch15\~20（均 1,400\~2,700 字/章）：退化为"场景号+字数区间"的分镜格式，对话变成极短的一行一句
- ch30\~40（均 1,150\~1,370 字/章）：进一步压缩为碎片式脚本（"黑暗。死寂。""海边。黄昏。"），叙事密度极低

这与第三节中"后期写不动、硬凑字"（语义重复 27%、叙事密度 50%、完整叙事文本 59%）等统计指标高度一致。

*证据 A2：工具幻觉——Ernie 16 次 vs Claude 0 次*

Ernie 在全部样本中共出现 16 次 tool_not_found 错误（调用不存在的工具，如 `finish`、`submit_final_answer`、`create_intent_json`、`str_replace_file` 等），Claude 在全部样本中 **0 次**。

*证据 A3：此前已知的 handoff 空摘要问题*

dsv1 版本中，handoff 机制的摘要生成输入包含完整的对话历史加 tool list。其他模型在这种输入下均能正常生成摘要，但 **Ernie 完全无法产出摘要内容**，导致 handoff 后丢失全部上下文。这个问题在 dsv2 中通过调整输入格式得以缓解，但进一步印证了 Ernie 在长上下文输入下的脆弱性。

**阶段 B：handoff 后——摘要丢失关键信息导致的产出退化**

handoff 后上下文已经重置（压缩为摘要），不存在"上下文太长"的问题。但如果摘要中缺少关键的创作信息，模型拿着一份不完整的摘要重新开始写作，就会退化为默认的产出模式。

*证据 B1：handoff 摘要内容质量的差异*

洞察 1 已经展示：Ernie 和 Claude 的 handoff 摘要长度相近（约 5,000\~6,000 字），但内容质量差距极大。Ernie 写出的是项目管理报告（文件列表、进度百分比），Claude 写出的是创作备忘录（叙事视角规则、肢体接触进度表、必保留台词）。摘要中缺少文风和创作细节，导致 Ernie handoff 后"不知道该怎么写"，退化为默认的大纲式产出。

*证据 B2：DRAMA_001 的 handoff 前后对比*

DRAMA_001 中 Ernie handoff 前写了 3 章正常正文（均 4,000 字/章），handoff 后上下文已重置，但产出立即退化为大纲格式（均 870 字/章）。这不是因为上下文太长——恰恰相反，此时上下文最短。退化的原因是摘要中没有保留"章节内容必须是完整正文而非大纲"这一关键信息。

注意：阶段 A 的退化会**传递到阶段 B**。摘要是在上下文接近窗口上限时生成的（此时模型已处于阶段 A 的退化状态），因此**摘要质量差本身可能也是阶段 A 退化的结果**——Ernie 在长上下文下无法有效提取关键信息来生成高质量摘要，进而导致 handoff 后阶段 B 的产出退化。

**这两个阶段共同解释了**上述洞察中的多个问题：后期章节越写越短（阶段 A）、handoff 后产出退化为大纲（阶段 B）、工具幻觉（阶段 A）、handoff 摘要质量差（阶段 A 传递到阶段 B）。
